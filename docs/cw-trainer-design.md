# CW モールス練習デバイス 設計書

> 作成：2026-11-21（更新：スマホ対応・RP2040 先行）
> 目的：エレキー＋練習アプリ一式の設計を、作る人が迷わず計画できる形でまとめる

---

## 1. 目的と背景

- アマチュア無線の **試験対策** と、**実際の交信（QSO）** ができるようになるための練習環境
- 「打つ（送信）」と「聞く（受信）」の両方を練習する
- **iPhone と PC** の両方で練習できる
- PC やスマホがなくても練習できる **オフライン練習** にも対応する
- パドルは市販品を 3.5mm ジャックにつなぐ

## 2. ゴール / 非ゴール / アンチゴール

**ゴール**
- 手元のパドルで打つと、遅延なくブザーが鳴る（iambic キーヤー）
- 受信練習：1文字（Koch 法）→ コールサイン → 定型 QSO 文 と段階的に上がれる
- 送信練習：打った符号を文字に解読し、タイミングのずれを見せる
- iPhone（USB-C）につなぐと、受信・筆記・送信のすべての練習ができる
- オフライン：OLED とブザーで「聞いて打ち返す」エコー練習ができる

**非ゴール**
- 和文モールス（英数字・記号のみ）
- スマホから機器の設定を変えること（設定は本体の OLED／PC から行う）
- Bluetooth 接続、ネイティブアプリ
- 実際の無線機へのキーイング出力

**アンチゴール（動いても失敗とみなすもの）**
- 打鍵音が遅れる・途切れる（PC・スマホ経由で音を鳴らす設計にしない）
- 設定のたびに PC が必要で、オフラインで使い物にならない

## 4. ファームウェア（Arduino / C++、earlephilhower Arduino-Pico コア＋Adafruit TinyUSB）

- **RP2040 / RP2350 の両方で同じソースがビルドできること**（電池関連の処理だけ切り替え）
- **キーヤー**：iambic Mode A / B と Ultimatic の切替、速度 5〜40 WPM、短点・長点メモリ
  - Ultimatic：両方を握ると、交互ではなく後から押した側を出し続ける（同時に押したら短点）
- **サイドトーン**：ブザー、周波数と ON/OFF を設定可能
- **解読**：打った符号を文字に変換（オフライン表示・PC 送信に使う）
- **USB 複合デバイス**：シリアル（CDC）＋ キーボード（HID）を同時に出す
- **オフラインモード**（OLED＋ボタン）
  - エコー練習：ブザーで出題 → パドルで打ち返す → 正解「ピッ」（1600Hz）／不正解は正解を再生
    - Koch の出題文字数は設定 ECHO LEN（1〜5、初期値 1）。初心者は1文字から始める
    - 設定 HINT（初期値 ON）で、出題の文字と符号（例 `-.-. --.-`）を画面に出す
  - 出題内容：Koch 文字 / コールサイン / 略語（CQ, DE, RST, 73 など）
  - 自由打鍵：解読結果を OLED に流して表示
  - 設定：WPM・モード・Koch レベル・トーン（スマホ利用時もここで設定）
- **設定の保存**：フラッシュに保存。PC アプリからも書き込める
- **電池残量**：RP2350 版のみ、可能なら OLED に表示

## 5. 機器との通信

### 5.1 PC：USB シリアル（Web Serial）

1行1コマンドのテキスト形式（デバッグしやすさ優先）。

```
PC → 機器:  SET WPM 20 / SET MODE B（A / B / U、U は Ultimatic） / SET TONE 700 / SET ECHOLEN 1 / SET HINT 1 / GET CONFIG / SAVE
機器 → PC:  E . 62        ← 要素（短点）とその長さ ms
            E - 185
            C A           ← 解読した文字
            CONFIG WPM=20 MODE=B TONE=700 ...
```

### 5.2 iPhone：USB キーボード（HID）

- キーヤーの出力（音が鳴っている間）を **1つのキーの押下／解放** として送る
- アプリは keydown / keyup の時刻から符号の長さを測り、アプリ側で解読する
- キーの割り当ては作る人が決める（iOS Safari で keydown / keyup が確実に取れるキーを実機で確認。文字入力欄にフォーカスがあっても誤入力にならないこと）
- iOS のキーリピートで keydown が連続するので、`event.repeat` を無視する
- PC でも同じ方式で使える（Web Serial 非対応ブラウザ向けの予備手段）
- **確定：キーは F13（HID 0x68）**。2026-11-21 に実機で確認（`tools/hid_test.html`、15WPM＝短点 80ms／長点 240ms）
  - PC（Chrome）：`key=F13 code=F13`、短点 76〜82ms、長点 238〜240ms
  - iPhone 17 Pro（Safari、USB-C 直結）：`key=F13 code=F13`、短点 71〜93ms、長点 218〜247ms
  - iPhone は受信時刻が ±10〜20ms 揺れる。アプリの打鍵分析は iPhone では許容幅を広めにとる

## 6. 練習アプリ（PWA）

- HTML＋JS の **PWA**（ホーム画面に追加でき、オフラインでも動く Web アプリ）
- 対応：iPhone Safari（実機：**iPhone 17 Pro**、USB-C で直結・給電）、PC の Chrome / Edge
- 配信：GitHub Pages（iPhone 向け。PWA と Web Serial は https が必要なため）と、PC の localhost（`tools/serve.ps1`）
- 受信音は端末のスピーカー（Web Audio）。Farnsworth（文字は速く・間は長く）対応
  - iOS は画面タップ後でないと音が出ないため、開始ボタンで音声を有効化する
- 機器がなくても受信練習・筆記練習はできる

**モード**
1. **受信：Koch 法** — 2文字から開始、正答率 90% 以上で1文字追加
2. **受信：コールサイン** — JA/JH/JR… や海外形式のランダム生成
3. **受信：定型 QSO** — ラバースタンプ QSO の文面、RST・名前・QTH をランダム化
4. **筆記（試験対策）** — 符号を「・－」表示 → 文字を答える／その逆
5. **送信練習** — 出題文を打つ → 解読結果と正誤、短点:長点比・字間のずれをグラフ表示（PC：シリアル、iPhone：キーボード入力）
6. **設定** — 機器の WPM・モード・トーンを読み書き（PC のみ）

- 進捗（Koch レベル・正答率履歴）はブラウザの localStorage に保存

## 7. ケース（3D プリント）

- **準備中**。FreeCAD で作り、ほかの CAD でも編集できる STEP と、印刷用の STL を公開する予定
- XIAO＋OLED＋ブザー＋スイッチを収め、3.5mm ジャック穴と USB-C 穴を持つ。RP2350 版のリポと電源スイッチの場所も確保する
- パドルは市販品を使う（3.5mm ステレオプラグ：先端＝短点、リング＝長点、根元＝GND）

## 8. 検討した方式

| 項目 | 候補 | 採用 | 理由 |
|---|---|---|---|
| ファーム | Arduino（C++） / CircuitPython | **Arduino** | ミリ秒単位のタイミング精度、C の経験が活かせる |
| アプリ | Web Serial のみ / PWA＋USB キーボード / BLE＋ネイティブアプリ | **PWA＋シリアル＋USB キーボード** | iPhone Safari は Web Serial・WebUSB・Web Bluetooth 非対応。キーボードなら iPhone でも打鍵タイミングが取れる。BLE は基板変更とネイティブアプリが必要で手間が大きい |
| オフライン | 自由打鍵のみ / エコー練習 / エコー＋OLED | **エコー＋OLED** | オフラインでも聞く・打つ・設定が完結する |
| マイコン・電源 | RP2040＋USB 給電 / RP2040＋充電モジュール / RP2350＋リポ | **当面 RP2040＋USB 給電、将来 RP2350＋リポ** | 手持ちの RP2040 で先に進める。RP2350 は電池と充電を内蔵しピン互換なので載せ替えが容易 |
